> Implementation plan for refactoring Lottie vector properties to dynamically parse either Primitive or Array values (a:0 vs a:1), supporting Split Positions (s:true), and adding core Gradient strokes/fills per official Lottie 1.0.1 specification rules.

## Goal

Ensure the `format` serialization layer can safely deserialize standard Lottie specification vectors (animated colors, split positions, gradients) without crashing, and provide corresponding renderer primitives for these vectors.

## Top-Level Test Strategy

A strictly Test-Driven Development (TDD) approach will be used. Tests will be created and explicitly fail before any implementation code is modified.

### 1. Unit Tests (`remotecompose/lottie/src/test/.../ParsingTest.kt`)
**Purpose:** Verify deserialization logic on isolated property strings without launching Compose or rendering trees.
**Specific Tests to write:**
- `parse_animatedColorProperty_parsesKeyframesArraySuccessfully`
- `parse_splitPositionProperty_parsesIndependentXandY`
- `parse_gradientFill_parsesColorStopsCorrectly`
- `parse_gradientStroke_parsesColorStopsCorrectly`

### 2. Integration Tests (`remotecompose/lottie/src/test/.../LottieDecoderResilienceTest.kt`)
**Purpose:** Verify the `LottieDecoder.decodeFromString` cleanly processes an entire Lottie file featuring these vectors.
**Specific Tests to write:**
- `decode_fileWithAnimatedColors_succeeds`
- `decode_fileWithSplitPosition_succeeds`

### 3. Acceptance / System Tests (`remotecompose/lottie/src/test/.../LottieFeatureDiffScreenshotTest.kt`)
**Purpose:** End-to-end verification that the parsed elements actually translate to valid pixels on screen matching the expected appearance. 
**Specific Tests to write:**
- Add `animated_color.json` to the test suite and verify `recordRoborazziDebug` matches expected frames.
- Add `split_position.json` to verify spatial coordinates map to the Remote Compose canvas correctly.
- Add `gradient_fill.json` to verify shader translation behaves as expected.
